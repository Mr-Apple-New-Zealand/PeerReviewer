### Summary  
A mobile web transfer times out (ERR_TXN_504) during a $250 inter-account transfer, causing the source account to be debited twice while the destination is credited once. This occurs because the retry button triggers a new transfer without an idempotency key (treated as a duplicate) and the debit/credit operations are not atomic. Three customers reported this in September 2026.  

### Current state  
- **Status**: In Progress (updated 2026-09-12 16:40)  
- **Owner**: Priya Nair  
- **Blocking progress**: PR #218 (wrapping debit/credit in a single transaction and adding idempotency key support) is pending code review. No other blockers mentioned.  

### Key details  
- **Steps to reproduce**:  
  1. Log in to mobile web, start a transfer between own accounts.  
  2. Introduce >30s latency (via toxiproxy) between API and database.  
  3. Tap Retry after "Request timed out (ERR_TXN_504)" appears.  
- **Affected components**: Transactions (component), mobile-web (labels).  
- **Affected versions**: 3.1.4 (confirmed in staging).  
- **Acceptance criteria**:  
  - Retry after timeout does not create duplicate transfers.  
  - Debit/credit operations are atomic (rollback if credit fails).  
  - Fix included in 3.2.0 release (target: 2026-09-24).
