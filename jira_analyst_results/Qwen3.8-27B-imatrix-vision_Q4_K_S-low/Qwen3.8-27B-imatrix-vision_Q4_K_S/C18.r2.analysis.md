## Grouping

### Group A — 401 auth failures causing unhandled TypeErrors

| Ticket | Events | Users | What the user sees |
|--------|--------|-------|--------------------|
| BANKUI-3C8 | 5,140 | 44 | (silent — handled, logged to console) |
| BANKUI-4A1 | 312 | 41 | UI crash on `/settlements/run/…` |
| BANKUI-4A2 | 289 | 39 | UI crash on allocation reports |
| BANKUI-4A9 | 104 | 33 | UI crash on allocation entry |
| BANKUI-4B3 | 97 | 31 | UI crash on batch actions |

**Shared signature:** All four TypeErrors have breadcrumbs showing one or more 401 responses from a bank-ui API endpoint in the seconds before the crash. The code receives a non-OK response, then tries to read a property (`sort`, `rows`, `returnProperties`, `length`) on what it expects to be a parsed data object but is actually `undefined`. All are `handled: false` — the user gets a broken page.

**Inference (high confidence):** BANKUI-3C8 is the upstream event; the four TypeErrors are downstream symptoms of the same root cause — the app does not guard against a 401 response body before passing it to render logic. The 401s themselves started at `2026-09-05T02:14:08Z` (BANKUI-3C8 firstSeen) and the TypeErrors follow within a second (BANKUI-4A1 and 4A2 both firstSeen at `02:14:09Z`).

**Two sub-problems to address:**
1. *Why* are the APIs returning 401? (auth/session/token issue — needs backend or auth-flow investigation)
2. *Why* does a 401 crash the UI instead of showing a login prompt or error banner? (frontend error-handling defect)

Sub-problem 2 is the one that turns a recoverable auth event into a user-facing crash, and it is fixable in bank-ui regardless of what is causing the 401s.

### Group B — Chrome extension (not our defect)

**BANKUI-2F0** — SecurityError, 4,812 events, **1 user**.

- Culprit is `chrome-extension://hdnmoggkpjoiaeldlphnmgejfcbkadkc/inject.js`
- No app breadcrumbs on any event
- All events from a single browser session
- The extension is attempting cross-origin frame access and being blocked by the browser's security policy

This is the exact failure mode Priya warned about in the ticket description ("top down by event count… turned out to affect one person"). The high event count is an artefact of one user having the extension enabled. **Action:** add this to the Sentry ignore list or create a rule to filter events whose `culprit` starts with `chrome-extension://`.

### Group C — Chunk load failure post-deployment

**BANKUI-5D6** — ChunkLoadError, 63 events, **58 users**.

- First seen `2026-09-10T21:11:36Z` — **6 minutes after the 4.7.0 deploy** (`2026-09-10T21:05:00Z`)
- The failing bundle is `6728.b4f17ce620a8d539.js`, which returns **404**
- Breadcrumbs show a navigation immediately before

**Inference (high confidence):** This is a stale-bundle / deployment race. Users who loaded the new `main` bundle from 4.7.0 request chunk 6728, but the server either hasn't finished serving the new chunk set or has already purged the old one. The 58-user count means this is not a one-off; it affected a significant portion of the user base during and shortly after the deploy.

**⚠️ Flag — URL mismatch:** The chunk is being requested from `https://bank-uat.example.com/…` but the Sentry query filters on `environment:Production`. Either:
- The production app is misconfigured to pull assets from a UAT domain, or
- Sentry environment tagging is incorrect for this project.

This needs clarification before we trust any other data in this export.

## Gaps and risks

- **Source maps not uploaded** (confirmed by Ravi's comment). Every `lastFrame` is a minified identifier (`ie.project`, `q.render`, `L.buildAction`, `N.setRows`). This makes it impossible to confirm the exact code location of the TypeErrors without guessing. Uploading source maps should be treated as a prerequisite for fixing Group A efficiently.
- **No acceptance criteria or reproduction steps** on the ticket. The "which two and why" question is answered above, but the underlying 401 root cause is unknown and may require backend team involvement.
- **Environment tagging question** (`bank-uat.example.com` in production data) could mean the entire export is from a mislabelled environment. If so, user counts and severity may be off.
- **BANKUI-3C8 is `handled: true`** — it will never crash the UI on its own, but its 5,140 events confirm the 401s are frequent and widespread. It should not be "fixed" by suppressing the log; it is the diagnostic signal for the auth problem.
