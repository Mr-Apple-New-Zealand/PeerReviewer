### Recommended work (capacity = 2 sprints)

**1. Fix 401 response handling (Group A) — work first**

- One fix resolves five issues. The app currently has no interceptor or guard for 401 responses; it falls through to code that assumes a successful payload and crashes on `.sort`, `.rows`, `.returnProperties`, `.length`.
- Evidence they are one bug:
  - 3C8 first-seen `02:14:08Z`; 4A1 and 4A2 first-seen `02:14:09Z` (one second later).
  - Breadcrumbs on 4A1/4A2/4A9/4B3 all explicitly reference preceding 401 responses.
  - 3C8 mechanism is `console` and `handled: true` — it's the app's own error logger catching the same 401 that then causes the TypeErrors.
- Affects 44 distinct users across settlements, payment batches, and allocation reports. This is the most user-impacting bug in the set.
- Likely fix: add an HTTP response interceptor (or per-service guard) that handles 401 before the response body is passed to rendering logic. Could also redirect to a login/re-auth flow.

**2. Fix chunk-loading after deploys (Group B)**

- First seen `21:11:36Z` on 09-10, six minutes after the 4.7.0 deploy at `21:05:00Z`. The requested file `6728.b4f17ce620a8d539.js` returns 404 — it existed in 4.6.0 but was removed in 4.7.0.
- Affects **58 users** (the highest per-issue user count in the set), meaning a wide slice of the production user base hit this in two days.
- Will recur on every future deploy unless addressed. Two complementary fixes:
  - **Deployment/CDN**: retain prior chunk files (or use a CDN cache policy that keeps them) so stale bundles can still resolve.
  - **App code**: catch `ChunkLoadError` and perform a full page reload (the new bundle will load correctly).
- Lower event count than Group A but wider user reach and a recurring risk.
