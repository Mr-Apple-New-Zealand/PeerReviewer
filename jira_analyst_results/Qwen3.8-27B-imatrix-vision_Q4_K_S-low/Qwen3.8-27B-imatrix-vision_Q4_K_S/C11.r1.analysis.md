- **Conflicting / undefined expected behaviour:** the message text implies a *mandatory* requirement ("To keep using… please log in…"), but Tom Becker explicitly questions whether it should block or merely warn. These two positions are not reconciled — flag rather than assume.
- **Defective copy (inference):** "fill **the customer's** questionnaire" is third-person/staff-facing phrasing leaking to an end user, and "To keep using mobile app" is ungrammatical. This looks like a template or localisation defect and will confuse any affected user, not just this one.
- **Dead-end UX:** the only control is **OK**, with no link/deep-link to Online Banking and no in-app questionnaire flow — so even if blocking is intended, the app does not tell the user how to resolve it.
- **Unknown trigger (inference):** because it reproduces on a test account too, the block is likely tied to an account/state condition (e.g. an incomplete "questionnaire"/eligibility flag) rather than a single corrupted profile. Which backend state or config drives it is not stated in the ticket.
