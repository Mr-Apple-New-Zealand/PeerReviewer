## 1. Summary

The direct cause of the user-reported "spins then fails" on saving a secondary branch is a **403 Forbidden returned by `masterfile-api`** during a Dapr service invocation. The payment routing rule handler calls `masterfile-api` to validate the branch, the call is rejected, the transaction rolls back, and the user sees a generic failure. There are two additional distinct issues in the log: a SQL conversion error on search queries, and escalating query timeouts in the pending payments module.

---

## 2. What is actually broken

### A. 403 Forbidden from masterfile-api (primary issue — matches user report)

| Detail | Value |
|--------|-------|
| Affected commands | `AddPaymentRoutingRuleSecondaryCommand`, `BulkUpdateSecondaryBranchesCommand` |
| Failing call | Dapr invocation to app-id `masterfile-api`, methods `branchlocation/get?ID=71&includeDetails=False` and `branchlocation/GetAll` |
| HTTP status | **403 Forbidden** |
| Occurrences | 4 (two full stack traces, two trimmed) at `[19:13:31]`, `[04:01:20]`, `[19:09:00]`, `[19:09:10]` |
| Code path | `MasterfileServiceClient.InvokeServiceGetAsync` / `InvokeServiceGetAllAsync` → handler → `TransactionBehaviour` → controller |

**Impact:** Any user attempting to save or bulk-assign a secondary branch on a payment routing rule will fail. This is a hard block — no workaround visible in the log.

**Severity:** High. This is the issue users are reporting.

**Likely cause (inference):** A Dapr service-to-service authentication/authorization failure. The `payments-api` service no longer has a valid identity or token accepted by `masterfile-api`. Common triggers: expired JWT, missing or rotated Dapr workload certificate, RBAC policy change on the target, or a deployment that changed the service account. The log only shows the caller side; the root cause is on the `masterfile-api` / Dapr platform side.

## 4. What the log does NOT let you determine

| Gap | Why it matters |
|-----|---------------|
| **Why masterfile-api returns 403** | The log is caller-side only. We need `masterfile-api` logs or Dapr platform/RBAC configuration to determine whether it's an expired token, missing identity, policy change, or sidecar misconfiguration. |
| **When the 403 started** | The log covers 48 h. Without a prior baseline or deployment log, we can't tell if this is new (e.g. after a cert rotation or deploy) or has been failing silently. |
| **The actual values in the SQL conversion error** | All three critical fields (value, column, data type) are masked as `******`. We cannot determine which row or filter triggers it without DB access or unmasking. |
| **Which users hit the 403** | The log doesn't include user identity or correlation IDs that tie the 403 errors back to the two reported users. |
| **Whether the GetStatementLineQuery degradation is related to the timeouts** | The long-running query warnings (see below) and the `GetMonitorJobs` timeouts are in different time windows and different modules. A shared database resource is possible but not provable from this log. |
| **Whether the `RunRoutingRuleGeneratorCommand` at `[21:06:09]` / `[21:06:09]` (two simultaneous) is a problem** | Two transactions with different IDs started in the same second. This could be legitimate concurrent users or a retry storm. No error followed, so it's unclear. |

## 5. Additional observation: escalating GetStatementLineQuery latency

From `[00:20:43]` to `[00:24:34]`, fourteen consecutive `GetStatementLineQuery` calls exceed the 10 s threshold, escalating from 35 s to **72 s**. This is in a different functional area (statements, not routing rules) but is a serious performance signal — it suggests a growing dataset, a missing index, or a query that degrades with data volume. Worth a separate ticket if not already tracked.

**Answer to Priya's specific question:** This is a **Platform / Dapr issue** (service-to-service 403), not a database issue. The database is involved in issues B and C, but the user-facing save failure is caused by the masterfile-api call being rejected before any database write for the secondary branch occurs.
