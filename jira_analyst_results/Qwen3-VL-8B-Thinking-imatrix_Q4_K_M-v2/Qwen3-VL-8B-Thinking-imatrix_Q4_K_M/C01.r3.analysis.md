### Summary  
A transfer timeout on mobile web causes duplicate debits when retrying after `ERR_TXN_504`. The source account is debited twice (e.g., $250), while the destination receives one credit. Confirmed by three customer reports and reproducible in staging with network latency.  

### Current state  
- **Status**: In Progress  
- **Owner**: Priya Nair  
- **Blocking progress**: Waiting for code review of PR #218 (wrapping debit/credit in a single transaction and adding Idempotency-Key support).  

### Key details  
- **Steps to reproduce**:  
  1. Log in via mobile web and initiate a transfer.  
  2. Add >30s latency (via toxiproxy) to trigger `ERR_TXN_504`.  
  3. Tap Retry (no Idempotency-Key header).  
- **Affected components**: Transactions (mobile web).  
- **Versions**: Affects 3.1.4; fix target: 3.2.0 (due 2026-09-24).  
- **Acceptance criteria**:  
  - Retry after timeout must not create a new transfer (idempotency key required).  
  - Debit and credit must be atomic (single database transaction).  
- **Missing**:

  - Verification of desktop web (no retry button) as a control.
