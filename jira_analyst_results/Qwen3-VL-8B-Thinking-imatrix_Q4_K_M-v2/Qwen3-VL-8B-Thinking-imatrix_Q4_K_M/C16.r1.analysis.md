# BANK-482: Statements page unusable since release 4.7.0

## Summary
The Statements page is taking over 35 seconds to load after release 4.7.0, with multiple GetStatementLineQuery calls exceeding 35,000ms. The GetAccountSummaryQuery remains at approximately 3.2 seconds before and after the release. The issue appears related to the ReindexStatementLines migration applied during 4.7.0 deployment, causing thread pool starvation and prolonged request times without corresponding changes to the AccountSummaryQuery.

## Current state
- Ticket status: Open with High priority
- Owner: Tom Becker
- Blocking issue: The problem is actively impacting production with customer complaints about statement loading times exceeding 1 minute
- No resolution path yet since the owner's comment suggests no statements-related changes were made in 4.7.0

## Key details
### Reproduction steps
1. Access a customer's statement in banking-prod environment
2. Observe load time exceeding 35 seconds after release 4.7.0

### Performance comparison
| Request Type | Before Release (4.6.3) | After Release (4.7.0) | Change |
|--------------|------------------------|------------------------|--------|
| GetStatementLineQuery | 281-319ms (max 319ms) | 35,171-72,974ms (avg ~40,000ms) | **133-240x slowdown** |
| GetAccountSummaryQuery | 3,102-3,341ms (avg ~3,200ms) | 3,188-3,402ms (avg ~3,200ms) | No change |
| ExportStatementCommand | 1,840ms | 1,902ms | Minimal change |

### Critical evidence
- **Mandatory migration**: Log shows `2026-09-14 21:05:36 [INF] Applied 1 pending migration: 20260914_2100_ReindexStatementLines` immediately after API startup
- **Thread starvation**: Log shows `ThreadPool starvation detected: 31 work items queued, 0 threads available for 4,200ms` during slow queries
- **Threshold warnings**: Multiple warnings show `Long-running request GetStatementLineQuery took [35k-72k]ms (threshold 10,000ms)`
