# OPS-92: Payments API: log dump for triage after user reports of failed saves

## Summary
Two users reported saving a secondary branch on a payment routing rule results in "just spins and then says it failed" without an error code. The log shows multiple failures during AddPaymentRoutingRuleSecondaryCommand and BulkUpdateSecondaryBranchesCommand operations with consistent 403 Forbidden errors when calling masterfile-api for branch location data. This matches the user-reported behavior but no specific error code is provided to the users.

## Current state
- Status: Open
- Priority: High
- Assignee: Unassigned
- Current blocker: Missing clear root cause identification from logs

## Key details
### Actual problem
- **Failed operations**: Multiple instances of AddPaymentRoutingRuleSecondaryCommand and BulkUpdateSecondaryBranchesCommand fail with 403 Forbidden errors when calling masterfile-api
- **Error pattern**: 
  - "Dapr.Client.InvocationException: An exception occurred while invoking method: 'branchlocation/get?ID=71&includeDetails=False' on app-id: 'masterfile-api' ---> System.Net.Http.HttpRequestException: Response status code does not indicate success: 403 (Forbidden)."
  - Occurs for specific branch IDs 71, 72, 73 and RuleSetIDs 41001, 41002, 41003
  - Seen during payment routing rule configuration operations

### Routine noise (can be ignored)
- SQL conversion errors ("Conversion failed when converting the ****** value '******' to data type ******") appear unrelated to the secondary branch saving issue
- Execution timeout errors (GetMonitorJobsQuery) indicate separate performance issues
- Long-running GetStatementLineQuery warnings (over 30 seconds) suggest performance issues but don't affect secondary branch saving
- Successful operations like "Request GetPaymentBatchActionListQuery completed in 1053ms" represent normal operation

### Missing information
- No details about why masterfile-api returns 403 (authorization, authentication, or configuration issue)
- No information about whether this is new or recurring problem
- No indication of which specific branches consistently fail versus intermittent issues
- No details about error handling in the application that would show if users are getting more specific error messages

## Risks and gaps

- **Component dependency**: The issue appears to be between payments-api and masterfile-api, but the log doesn't clarify ownership (ticket comments state: "Platform will want to know whether this is us or the database team")
- **Conflict**: Ticket description states users "just spins and then says it failed" with no error code, but log shows specific errors that could have been presented to users
