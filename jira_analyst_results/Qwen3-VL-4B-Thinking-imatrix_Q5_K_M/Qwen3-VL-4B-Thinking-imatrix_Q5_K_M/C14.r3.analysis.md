# OPS-92 Analysis

## Summary
Two users reported that saving secondary branches on payment routing rules "just spins and then says it failed" without error codes. The log shows multiple failures when the Payments API attempts to access branch location data from the masterfile-api service, specifically returning 403 Forbidden errors for calls like 'branchlocation/get?ID=71&includeDetails=False'. There are also database conversion errors and query timeouts, but the core issue appears to be related to failed API calls to masterfile-api when trying to add secondary branches.

## Current State
- Status: Open | Priority: High
- Owner: Unassigned
- Blocking progress: The API cannot complete secondary branch saves due to service call failures. Support has provided a 48-hour log dump but doesn't clarify if this is a platform or database issue. Priya Nair's comment indicates the platform team needs to determine ownership before they can proceed.

## Key Details
- **Steps to reproduce**: Attempting to save a secondary branch to a payment routing rule (specifically the AddPaymentRoutingRuleSecondaryCommand and BulkUpdateSecondaryBranchesCommand operations).
- **Affected components**: Payments API, masterfile-api service, and database
- **Error patterns**:
  - 403 Forbidden errors when calling 'branchlocation/get' and 'branchlocation/GetAll' from masterfile-api
  - Multiple "Conversion failed when converting the ****** value '******' to data type ******" errors
  - "Execution Timeout Expired" for GetMonitorJobsQuery
  - Long-running requests (GetStatementLineQuery taking over 40 seconds)
- **Missing information**:
  - Specific data causing 403 errors in masterfile-api calls
  - Why the 403 errors are happening (authentication? permissions?)
  - Whether these issues occur for all users or specific routing rules
  - Confirmation if the database connection is working properly (separate from API calls)

## Risks and Gaps
- **Ambiguity**: The log shows multiple issues, but it's unclear if these are related to the reported "failed save" problem. The 403 errors appear to be the primary cause of the failed saves, but this needs confirmation.
- **Dependencies**: The issue likely involves coordination between Payments API and masterfile-api services, but the root cause is unclear. The log shows the Payments API is trying to call masterfile-api, but doesn't explain why it's failing.
- **Missing data**: No specific error details from the masterfile-api service, making it hard to determine if this is a configuration issue in masterfile-api or Payments API.
- **Related tickets**: No links to other tickets mentioned, but there may be duplicates or related issues.
- **Inference**: The reported "failed save" problem is most likely caused by the 403 Forbidden errors when trying to get branch location data. However, the log doesn't confirm this is the *only* issue causing the user-reported problem.

## Suggested Next Actions
- **Immediate**: 
  - Review the masterfile-api service logs to determine why branch location calls are returning 403 Forbidden. Check if the service's authentication is properly configured for the Payments API.
  - Validate if the Payments API has proper permissions to call masterfile-api, particularly for branch location data.
- **Medium term**:
  - Cross-check the user reports with specific routing rules where secondary branch saving was attempted. Determine if the failure pattern is consistent across the platform or specific to certain rules.
  - Investigate the database conversion errors to identify potential data type mismatches.
- **Ownership clarification**:
  - Prioritize determining whether the issue is a Payments API configuration problem or a masterfile-api service issue, as suggested by Priya Nair's comment. The platform team needs to decide who owns this.
  - Document whether the issue occurs with specific branch IDs or routing rules to help narrow down the problem.
