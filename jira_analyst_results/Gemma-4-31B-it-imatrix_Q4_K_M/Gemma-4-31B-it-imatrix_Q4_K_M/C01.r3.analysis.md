**Summary**
Retrying a failed transfer on mobile web leads to a double debit of the source account while only crediting the destination account once. This occurs because the retry request lacks an idempotency key and the debit/credit operations are not processed as a single atomic transaction.

**Current State**
*   **Status:** In Progress.
*   **Owner:** Priya Nair.
*   **Blocking Progress:** Pending code review for PR #218.

**Key Details**
*   **Steps to Reproduce:** 
    1. Log in via mobile web.
    2. Initiate a transfer between owned accounts.
    3. Introduce >30s latency between API and database (using toxiproxy).
    4. Upon receiving "Request timed out (ERR_TXN_504)", tap the Retry button.
*   **Affected Version:** 3.1.4 (specifically mobile web; Tom Becker confirmed desktop web is not affected as it disables the submit button and lacks a Retry button).
*   **Acceptance Criteria:** Missing.
*   **Fix Version:** 3.2.0.
