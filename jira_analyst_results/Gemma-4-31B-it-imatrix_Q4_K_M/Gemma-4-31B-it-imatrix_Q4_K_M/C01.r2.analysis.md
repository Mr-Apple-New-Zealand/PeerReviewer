**Summary**
Users on mobile web experiencing a timeout (ERR_TXN_504) during a transfer are debited twice if they use the "Retry" button. This occurs because the system does not use atomic transactions for debits and credits, and the retry request lacks an idempotency key.

**Current state**
*   **Status:** In Progress
*   **Owner:** Priya Nair
*   **Blocking progress:** PR #218 is awaiting code review.

**Key details**
*   **Steps to reproduce:**
    1. Log in to mobile web and start a transfer between two own accounts.
    2. Use toxiproxy to add >30s latency between the API and the database.
    3. Tap "Retry" when the "Request timed out (ERR_TXN_504)" error appears.
*   **Affected components/versions:** Transactions component; version 3.1.4.
*   **Acceptance criteria:** Missing (though "Expected" behavior is defined as one debit and one credit).

**Risks and gaps**
*   **Financial Impact:** Three customers have been incorrectly debited; these require manual reversals by Finance Ops.
*   **Inconsistency:** Tom Becker noted that the issue does not occur on desktop web because that platform disables the submit button and lacks a "Retry" button.
*   **Dependencies:** The fix is dependent on the merge of PR #218 to meet the 3.2.0 release target (2026-09-24).
