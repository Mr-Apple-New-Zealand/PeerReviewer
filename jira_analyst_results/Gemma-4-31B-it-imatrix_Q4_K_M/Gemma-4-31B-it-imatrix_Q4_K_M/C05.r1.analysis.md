**BANK-425 is a duplicate of BANK-440.** Both describe a failure of the web dashboard to update the account balance after a transfer in version 3.1.4.

### Summary
The web dashboard fails to reflect updated balances after a transfer because the balance is cached in local storage for 15 minutes. While the API returns the correct data, the frontend does not invalidate the `BalanceCache` upon a successful transaction.

### Key Details
*   **Affected Version:** 3.1.4 (Web).
*   **Root Cause:** Local storage caching of `GET /api/user/balance` for 15 minutes (introduced in BANK-419).
*   **Reproduction:** Perform a transfer $\rightarrow$ observe balance on web dashboard $\rightarrow$ balance remains old $\rightarrow$ logout/login or wait 15 minutes to see update.
*   **Acceptance Criteria:** Missing from all tickets.

### Risks and Gaps
*   **Inference:** BANK-419 is the direct cause of BANK-440 and BANK-425. The effort to reduce API calls created a regression where successful transfers do not trigger a cache refresh.
*   **Distinction:** MOB-88 is **not** a duplicate; it is a separate issue involving the backend notification service using the wrong event (`TransferRequested` instead of `TransferCompleted`) for mobile push notifications.
*   **Missing Information:** There are no formal links between the related tickets.
