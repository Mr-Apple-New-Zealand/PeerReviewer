### Summary
The application crashes with a `TypeError` when a user attempts to perform actions after their session has expired (approximately 3 hours of inactivity). The UI does not gracefully handle `401 Unauthorized` responses from the API, attempting to call methods like `.sort()`, `.rows`, and `.returnProperties` on undefined response data.

### Session Analysis
Based on the breadcrumbs in `sentry-event-a17f3c9d.json`, the user's session followed this sequence:
1. **Active Period:** The user performed several successful operations (status 200) involving settlement allocations and a token refresh at `1789182766`.
2. **Inactivity:** There is a gap of approximately 3 hours (from `1789182813` to `1789197792`) where no activity is recorded.
3. **Session Expiry:** Upon returning, the user clicked a dropdown item, triggering a series of API calls. Every subsequent request (including `GetAllRunBookingsForCustomerOrder`, `Branch/Query`, and `PaymentBatch/Get`) returned a **401 Unauthorized** status.
4. **Cascading Failures:** The application attempted to process these failed responses, leading to three distinct crashes in the session:
    *   `Cannot read properties of undefined (reading 'rows')`
    *   `Cannot read properties of undefined (reading 'returnProperties')`
    *   `Cannot read properties of undefined (reading 'sort')` (The primary error reported in BANK-495).

### Underlying Defect
The defect is a **lack of error handling for failed API responses** in the Web UI. The frontend code assumes that API calls will return a valid object or array and immediately calls methods on that data without verifying if the request was successful or if the response body exists. 

Specifically, the error reported in the ticket occurs when the code attempts to call `.sort()` on the result of a failed `PaymentBatch/Get` or `PaymentBatch/Actions` call.

### Indeterminate Information
The provided Sentry event does not allow for the determination of:
*   **Exact Source Code Location:** The JavaScript is minified and not symbolicated (e.g., the function is listed as `ie.project` in `6728.b4f17ce620a8d539.js`), so the specific line of code cannot be identified.
*   **Actual Environment:** There is a conflict between the Sentry tag `environment: Production` and the URL `https://bank-uat.example.com`, making it unclear if this is occurring in UAT or Production.
*   **Auth Logic Failure:** It is unclear why the automatic token refresh (seen earlier in the session) did not trigger or succeed after the 3-hour gap.

### Suggested Next Actions
*   **Developer (Tom Becker):** Implement null/undefined guards (or optional chaining) before calling `.sort()`, `.rows`, and `.returnProperties` on API response data.
*   **Developer:** Implement a global HTTP interceptor to handle `401 Unauthorized` errors centrally (e.g., redirecting to login or forcing a session refresh) rather than allowing the request to propagate to the component logic.
*   **QA:** Verify if the "Production" environment is actually affected or if this is isolated to the UAT environment.
