**Summary**
A bug in the mobile web transfer process causes a source account to be debited twice if a user selects "Retry" after a timeout (ERR_TXN_504). This happens because the debit and credit operations are not wrapped in a single database transaction and the retry request lacks an idempotency key.

**Current State**
*   **Status:** In Progress
*   **Owner:** Priya Nair
*   **Blocking Progress:** Pending code review for PR #218.

**Key Details**
*   **Steps to Reproduce:** 
    1. Log in to mobile web and start a transfer between own accounts.
    2. Use toxiproxy to add >30s latency between API and database.
    3. Tap "Retry" when ERR_TXN_504 appears.
*   **Affected Components/Versions:** Transactions component; version 3.1.4.
*   **Acceptance Criteria:** Not explicitly defined, though the expected result is "one debit and one credit" regardless of retries.
*   **Fix Version:** 3.2.0 (Target date: 2026-09-24).

**Risks and Gaps**
*   **Missing Information:** The ticket does not list explicit acceptance criteria.
*   **Dependencies:** Three affected customers require manual debit reversals via Finance Ops.
*   **Inference:** The bug is specific to the mobile web implementation; Tom Becker noted it does not reproduce on desktop web because the desktop UI disables the submit button and lacks a "Retry" button.
