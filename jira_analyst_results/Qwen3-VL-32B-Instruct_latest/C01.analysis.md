**Summary**  
A bug in the mobile web transfer flow causes the source account to be debited twice when a transfer times out and the user retries. This occurs because the retry sends a new request without an idempotency key, and the debit and credit operations are not atomic. Three customers have been affected, requiring manual reversals. The fix involves wrapping debit/credit in a single transaction and adding idempotency support.
