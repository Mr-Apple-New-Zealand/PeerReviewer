### Incident Timeline

- **09:31 NZST**: Errors start appearing in dashboards.
- **09:47 NZST**: Monitoring alert fires due to TransferErrorRate exceeding 20%.
- **09:52 NZST**: Incident declared by Sam Okafor; error rate at 64%.
- **10:05 NZST**: Marcus Reid reports a spike in the support queue with 40+ calls in the last 15 minutes.
- **10:10 NZST**: Priya Nair suggests database issues as a potential cause, noting slow queries on the transactions table.
- **10:24 NZST**: Sam Okafor identifies the issue: failing requests are 401s from the Transactions API with error "IDX10503: Signature validation failed". Links it to the JWT signing key rotation in OPS-81.
- **10:31 NZST**: Sam Okafor initiates rollback of the OPS-81 config deploy.
- **10:42 NZST**: Transfer error rate returns to under 1% after rollback completion.
- **10:50 NZST**: Incident resolved; root cause documented.

### Time Calculations

- **Time to Detect**: From the start of errors at 09:31 to the incident declaration at 09:52, it is 21 minutes.
- **Time to Recover**: From the incident declaration at 09:52 to recovery at 10:42, it is 50 minutes.

### Root Cause

The root cause was the JWT signing key being rotated in config deploy OPS-81 without updating the key that the Transactions API validates against. This resulted in the Transactions API rejecting tokens issued by the Auth service due to a signature validation failure.
