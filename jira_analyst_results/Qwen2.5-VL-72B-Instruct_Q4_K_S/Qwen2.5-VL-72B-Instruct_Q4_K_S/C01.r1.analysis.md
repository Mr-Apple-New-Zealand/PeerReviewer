### Summary
The bug in BANK-412 causes a source account to be debited twice when a customer retries a timed-out transfer between their own accounts on mobile web. This issue has affected three customers and is due to the lack of idempotency in retry handling and improper transaction management.

### Current State
- **Status:** In Progress
- **Owner:** Priya Nair
- **Blocking:** Waiting for code review of PR #218, which addresses the technical issues by wrapping debit and credit operations in a single transaction and adding support for an Idempotency-Key header.

### Key Details
- **Steps to Reproduce:**
  - Log in on mobile web.
  - Start a transfer between two own accounts.
  - Introduce more than 30s of latency between the API and database.
  - Tap Retry after ERR_TXN_504 appears.
  
- **Affected Components/Versions:** Transactions component, version 3.1.4.
- **Acceptance Criteria:**
  - The debit and credit operations should be wrapped in a single transaction to ensure atomicity.
  - The transfer endpoint should support the Idempotency-Key header to prevent duplicate transactions on retry.

### Risks and Gaps
- **Ambiguities:** It is unclear if the fix will fully resolve the issue for all affected customers or if additional manual corrections are still needed.
- **Missing Information:** No details on the impact assessment of the PR #218 or potential regression testing plans.
- **Dependencies:** The ticket depends on the successful code review and merge of PR #218. There is also a dependency on Finance Ops to manually reverse duplicate debits for affected customers.
