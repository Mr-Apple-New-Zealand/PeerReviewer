### Summary
The bug causes the source account to be debited twice when a customer retries a timed-out transfer between two accounts on mobile web. This issue has affected three customers and is due to the lack of idempotency in retry logic and improper transaction handling.

### Current State
- **Status:** In Progress
- **Owner:** Priya Nair
- **Blocking:** Waiting for code review of PR #218, which addresses the root causes identified.

### Key Details
- **Steps to Reproduce:**
  - Log in on mobile web and initiate a transfer between two own accounts.
  - Introduce more than 30 seconds of latency between the API and database.
  - When the "Request timed out (ERR_TXN_504)" error appears, tap Retry.

- **Affected Components/Versions:** Transactions component, version 3.1.4 affected; fix targeted for version 3.2.0.

- **Acceptance Criteria:**
  - The retry mechanism should not result in duplicate debits.
  - Debit and credit operations should be wrapped in a single database transaction to ensure atomicity.
  - The transfer endpoint should support the Idempotency-Key header to prevent duplicate transactions.
