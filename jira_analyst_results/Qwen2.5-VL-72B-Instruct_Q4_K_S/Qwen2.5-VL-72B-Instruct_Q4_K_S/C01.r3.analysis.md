### Summary
The bug causes the source account to be debited twice when a customer retries a timed-out transfer between their own accounts on mobile web. This issue has affected three customers and is due to the retry mechanism not using an idempotency key and the debit/credit operations not being in a single transaction.

### Current State
- **Status:** In Progress
- **Owner:** Priya Nair
- **Blocking:** Waiting for code review of PR #218, which addresses the issue by wrapping debit and credit in a single transaction and adding idempotency key support.

### Key Details
- **Steps to Reproduce:**
  - Log in on mobile web.
  - Start a transfer between two own accounts.
  - Introduce more than 30 seconds of latency between the API and database.
  - When "Request timed out (ERR_TXN_504)" appears, tap Retry.

- **Affected Components/Versions:**
  - Component: Transactions
  - Affects version: 3.1.4

- **Acceptance Criteria:** 
  - One debit and one credit should occur per transfer.
  - The retry mechanism should use an idempotency key to prevent duplicate transactions.
  - Debit and credit operations should be within a single database transaction.

### Risks and Gaps
