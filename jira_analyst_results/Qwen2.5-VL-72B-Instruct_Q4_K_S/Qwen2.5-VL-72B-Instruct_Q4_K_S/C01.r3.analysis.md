### Summary
The issue is that retrying a timed-out transfer on mobile web results in the source account being debited twice while the destination account is credited only once. This has affected three customers and is due to the lack of idempotency in the retry mechanism and separate database transactions for debit and credit operations.

### Current State
- **Status:** In Progress
- **Owner:** Priya Nair
- **Blocking:** The ticket is waiting on code review for PR #218, which aims to fix the issue by wrapping debit and credit in a single transaction and adding idempotency key support.

### Key Details
- **Steps to Reproduce:**
  - Log in on mobile web.
  - Start a transfer between two own accounts.
  - Introduce more than 30 seconds of latency between the API and database.
  - Tap Retry when ERR_TXN_504 appears.
  
- **Affected Components/Versions:** Transactions component, version 3.1.4.
- **Acceptance Criteria:** The expected behavior is one debit and one credit per transfer. The actual behavior currently results in two debits and one credit. The criteria are not explicitly stated but can be inferred from the steps to reproduce and the expected vs. actual outcomes.
