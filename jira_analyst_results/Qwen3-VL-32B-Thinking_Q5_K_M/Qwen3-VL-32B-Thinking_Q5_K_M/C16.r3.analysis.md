# Log Comparison Analysis for BANK-482

## Log Comparison Summary
- **GetStatementLineQuery performance** regressed from ~300ms to ~50,000ms, making it 166x-243x slower after 4.7.0 release
- **GetAccountSummaryQuery** performance remained stable (3,100ms vs 3,200ms)
- The 4.7.0 deployment included a database migration "20260914_2100_ReindexStatementLines" that appears to have caused the regression

## Performance Regression Quantification

### GetStatementLineQuery (Key Issue)
- **Before 4.7.0 (4.6.3):** 10 requests, 281-319ms (avg 300ms)
- **After 4.7.0 (4.7.0):** 12 requests, 35,171-72,974ms (avg 50,000ms)
- **Regression factor:** 166x-243x slower (50,000ms/300ms)
- **All post-4.7.0 requests** exceeded the 10,000ms threshold, triggering warning logs

### GetAccountSummaryQuery (No Regression)
- **Before 4.7.0:** 4 requests, 2,987-3,341ms (avg 3,100ms)
- **After 4.7.0:** 4 requests, 3,011-3,402ms (avg 3,200ms)
- **Slight improvement:** 1.4% faster in the after log

### Other Notable Metrics
- **ThreadPool starvation:** "31 work items queued, 0 threads available for 4200ms" after 4.7.0
- **Health check:** Slightly increased from 6ms (4.6.3) to 9ms (4.7.0) - not significant
- **ExportStatementCommand:** 1840ms vs 1902ms - no meaningful change

## What Changed vs What Did Not

### Key Changes (After 4.7.0)
- **Significant slowdown** in GetStatementLineQuery (166x-243x regression)
- **New database migration** "20260914_2100_ReindexStatementLines" applied
- **Thread pool issues** (starvation detected)
- **All GetStatementLineQuery requests** now trigger warnings (exceeding 10,000ms threshold)
- **Increased request volume** (12 GetStatementLineQuery calls in after log vs 10 before)

### What Remained Stable
- GetAccountSummaryQuery performance (3,100ms to 3,200ms)
- ExportStatementCommand execution time (1,840ms to 1,902ms)
- Database health check (6ms to 9ms)
- Number of GetAccountSummaryQuery requests (4 in both logs)

## What These Logs CANNOT Establish

1. **Root cause of regression:** The logs confirm GetStatementLineQuery is slow but don't show why (e.g., database index, code change, or configuration issue)
2. **Whether the 4.7.0 migration caused the issue:** The log shows the migration ran, but correlation ≠ causation
3. **Specific component at fault:** Could be database, API service, or external dependency
4. **Impact on user experience:** While "times out in the browser" is reported, the logs don't capture actual browser behavior
5. **Whether 4.7.0 actually contained changes beyond notifications/admin:** Tom Becker's comment claims no statements changes were made
6. **When the performance issue began:** The logs only show a before/after comparison, not a continuous timeline
7. **If the issue was introduced at deployment or after:** The migration could have been run after the release

## Additional Context from the Ticket
- The "4.7.0" release was reported by Tom Becker to only contain "notifications and the admin screens" (not statements functionality)
- Ravi Kumar suggests "the account summary query" is the issue, but the logs show it's stable while GetStatementLineQuery is the problem
- The customer impact is severe: "opening a customer's statement either takes over a minute or times out" with branch staff telling customers to call back
