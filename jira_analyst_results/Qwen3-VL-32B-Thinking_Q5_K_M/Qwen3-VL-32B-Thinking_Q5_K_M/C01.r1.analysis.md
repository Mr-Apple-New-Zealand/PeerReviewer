## Summary
When users retry a failed transfer after a timeout on mobile web, the system debits the source account twice and credits the destination account once. This occurs because the retry request lacks an idempotency key, and the debit and credit operations are not part of a single database transaction. Three customers have already been affected and require manual reversal of duplicate debits.

## Key details
- **Steps to reproduce**: 
  - Log in on mobile web and start a transfer between two own accounts
  - Add more than 30s of latency between API and database
  - Tap "Retry" when ERR_TXN_504 appears
