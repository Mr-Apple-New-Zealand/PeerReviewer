## What is actually broken (and how badly)

1. **Secondary branch save fails — matches the reported bug. Severity: High.**
   - `AddPaymentRoutingRuleSecondaryCommand` (RuleSetId 41001, SecondaryBranchID 71) fails with:
     `Dapr.Client.InvocationException: ... invoking method: 'branchlocation/get?ID=71&includeDetails=False' on app-id: 'masterfile-api' ---> ... 403 (Forbidden)`
   - The same error recurs for RuleSetId 41002, SecondaryBranchID 71.
   - `BulkUpdateSecondaryBranchesCommand` also fails the same way calling `branchlocation/GetAll` on `masterfile-api` (403 Forbidden), twice in the log.
   - This is a downstream authorization failure, not a database error — payments-api cannot call `masterfile-api` to resolve branch details when adding/updating a secondary branch. That directly explains a save that "spins and then fails" with no user-facing error code, since the UI likely has no mapping for a raw 403 from an internal service call.

2. **SQL data conversion error on rule search — real, but separate. Severity: Medium.**
   - `SearchPaymentRoutingRuleQuery` repeatedly throws `SqlException ... Conversion failed when converting the ****** value '******' to data type ******.` (Error 245) — recurring at least 6 times across the window.
   - This affects search/listing, not the secondary-branch save the users reported.

3. **DB timeouts on monitor jobs — real, but separate. Severity: Medium.**
   - `GetMonitorJobsQueryHandler` throws `Execution Timeout Expired` repeatedly in a burst (22:26–22:29), Error Number -2. Distinct feature (pending payment monitoring), not the reported bug.

4. **Escalating slow query on statement lines — worth watching. Severity: Medium/trend.**
   - `GetStatementLineQuery` goes from ~35s to ~72s (threshold 10s) over a few minutes late in the window — a worsening trend that could turn into timeouts if it continues, similar in shape to item 3.
