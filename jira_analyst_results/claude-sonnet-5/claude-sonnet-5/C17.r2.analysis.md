## Summary

The attached Sentry event shows a session where the batch actions screen (`/payments/batch/actions`) crashed with `TypeError: Cannot read properties of undefined (reading 'sort')` after the user's session/auth token appears to have expired following a long idle period. The event confirms the "blank screen" symptom is a side effect of an unhandled Angular exception, but the stack trace has been trimmed and never symbolicated, so it does not show the actual application code responsible.

## What happened in the user's session (from breadcrumbs)

- **~1789182659–1789182813** (real timestamps, not shown as dates): normal working session — repeated `SettlementAllocation/Query`, `GetAllocationLineMarketPlanDetail`, `InvokeAction` calls all returning `200`, plus ag-grid input edits and button clicks. One token refresh (`/api/security/token/refresh`) succeeds mid-session (`200`).
- **A gap of ~14,979 seconds (≈4.16 hours)** then follows with no breadcrumbs at all, until the next `ui.click`. This lines up with the ticket's own note that the problem "seems to happen to people who have had the tab open a while."
- Immediately after the idle gap, the user clicks a dropdown item, and from that point **every subsequent API call fails with `401` and an empty body** (`GetAllRunBookingsForCustomerOrder`, `Branch/Query`, `ClearanceType/GetAll`, `GetAllDistinctCustomerGroup`, `Period/Query`, `CustomerOrder/Search`, `InvokeAction`, `PaymentBatch/Get`, `PaymentBatch/Actions`).
- Interleaved with these 401s, the client throws **four separate `TypeError: Cannot read properties of undefined` errors** in quick succession (reading `'rows'` ×2, `'returnProperties'`, `'length'`), before the final one — reading `'sort'` — which is the exception this Sentry event actually reports.
- The user continues navigating (`allocation-reports` → `allocation-entry` → back → `batch/actions`) while the 401s and TypeErrors keep occurring, consistent with "the screen sometimes goes blank" rather than a single click-and-crash.

## Underlying defect (inference)

- **Inference, based on the timing correlation**: the session's auth expired after the long idle period. Once calls started returning `401` with empty response bodies, several parts of the UI treated the (missing) response payload as if it were a normal successful response and tried to read properties off `undefined` — `.rows`, `.returnProperties`, `.length`, and finally `.sort`.
- This matches Tom Becker's comment that something is calling `.sort` on an array that isn't there — but the breadcrumbs suggest it's not one isolated bug; it's a **pattern of missing null/undefined guards across multiple screens/services** whenever an API call fails, not a single line of code.
- The crash is reported as `handled: "no"` via Angular's global error handler, which is consistent with the whole component tree unmounting and the screen going blank.

## What this event does not let you determine

- **The actual application code path.** All stack frames are minified/unsymbolicated (`js_no_source`, `symbolicated_in_app: false`) and limited to RxJS/Zone.js internals (`invokeTask`, `runTask`, `ie.project`, etc.). Support's own note confirms **28 further frames in the same rxjs error-propagation chain were trimmed**, so the frame that actually calls `.sort()` is not in this file at all.
- **Which of the four TypeErrors in the session is the "real" defect.** Only the `'sort'` one was captured as a standalone reported event here; the `'rows'`, `'returnProperties'`, and `'length'` errors are visible only as breadcrumb summaries with their own `event_id`s — their full events aren't attached.
- **Whether the root cause is expired auth, a server-side session timeout, or something else.** The correlation with the 401 burst is strong but the event doesn't include why auth failed (e.g., token TTL, server-side logout, revoked session).
- **The environment.** There's a real conflict here: the Sentry `environment` tag and top-level field say `"Production"`, but every URL in the event (`request.url`, all breadcrumb URLs, `errors[].url`) points to **`bank-uat.example.com`**, a UAT hostname. This is exactly what Tom Becker asked to confirm before treating it as a production incident — and it should be resolved before prioritizing this as a live prod incident.
