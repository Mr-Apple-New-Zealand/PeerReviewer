## Summary

Sentry captured an unhandled `TypeError: Cannot read properties of undefined (reading 'sort')` on `/payments/batch/actions` in a session that also produced three earlier, different "Cannot read properties of undefined" errors, all following a cascade of HTTP 401 responses after several hours of inactivity. The pattern in the raw event points to a session/auth-expiry problem cascading into multiple unguarded property accesses, not a single isolated `.sort()` bug — this is broader than Tom Becker's comment suggests.

## What happened in this session (from breadcrumbs)

- **~1789182659–1789182813** (first active block): normal use — `SettlementAllocation/Query`, `GetAllocationLineMarketPlanDetail`, `InvokeAction` calls all return `200`, user edits ag-Grid numeric fields, clicks buttons. A `token/refresh` call succeeds at `1789182766`.
- **Gap of ~4.2 hours** (`1789182813` → `1789197792`) with no breadcrumbs — consistent with the ticket's note that this "seems to happen to people who have had the tab open a while."
- **From `1789197792` onward**: the user resumes interacting (clears a dropdown value, opens a dropdown, clicks an item). Immediately, essentially **every subsequent API call returns `401`**: `GetAllRunBookingsForCustomerOrder`, `Branch/Query`, `ClearanceType/GetAll`, `GetAllDistinctCustomerGroup`, `Period/Query`, `CustomerOrder/Search`, `SettlementAllocation/InvokeAction`, `PaymentBatch/Get`, `PaymentBatch/Actions` — across unrelated modules (masterfile, settlements, hq, payments).
- Interleaved with those 401s are **four separate `TypeError` breadcrumbs** in the same session, in this order:
  1. `Cannot read properties of undefined (reading 'rows')` ×2
  2. `Cannot read properties of undefined (reading 'returnProperties')`
  3. `Cannot read properties of undefined (reading 'length')`
- The user continues navigating (`allocation-reports` ↔ `allocation-entry` ↔ `/payments/batch/actions`), triggering more 401s.
- The **captured/reported exception** — `Cannot read properties of undefined (reading 'sort')` — fires right after the final navigation back to `/payments/batch/actions`, immediately following two more 401s on `PaymentBatch/Get` and `PaymentBatch/Actions`.

**Inference:** the screen-blanking behaviour coincides with the session's authentication having lapsed (repeated 401s across many endpoints simultaneously), not with any specific data condition on the batch actions screen itself. This is based on the timing correlation in the breadcrumb trail, not on source code, so it is an inference rather than a confirmed cause.

## Underlying defect (inference)

- Multiple UI components (at least whatever renders `rows`, `returnProperties`, `length`, and `sort` on some response object) appear to assume a successful API response body and access properties on it **without checking for a failed/empty response**. When the backend returns `401` with an empty body, the calling code still tries to read `.rows`, `.length`, `.returnProperties`, `.sort` off `undefined`, and the resulting unhandled exception is what blanks the screen (consistent with Operations' report of needing to reload).
- Tom Becker's comment ("something is calling `.sort` on an array that isn't there") is correct for the *reported* exception, but the breadcrumbs show this is one instance of a **recurring pattern across the session**, not an isolated defect — a guard on `.sort` alone would likely leave the `.rows`/`.length`/`.returnProperties` failures unaddressed.
- Root question — *why* the session became fully unauthenticated after ~4 hours (token refresh not retried, refresh token itself expired, or a bug in silent-refresh logic) — **cannot be determined from this event**; it only shows the effects (401s), not the auth/session-handling code.
