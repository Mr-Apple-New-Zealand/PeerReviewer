## Duplicate assessment

**Yes — BANK-440 is very likely a duplicate of BANK-425.**

- Both describe the same symptom: web dashboard/home screen balance doesn't reflect a completed transfer (BANK-440: "the balance on the web dashboard still shows the old value"; BANK-425: "the balance shown on the home screen (web) is out of date").
- Both affect version 3.1.4.
- BANK-440 confirms the API returns the correct value immediately, which matches Hana Sato's root-cause finding on BANK-425: the front end caches the balance in local storage (`BalanceCache`) for 15 minutes and nothing invalidates it after a transfer.
- BANK-425 was raised earlier (2026-09-05) than BANK-440 (2026-09-13), so BANK-425 is the original.

**MOB-88 is not a duplicate** — different platform (mobile push notification vs. web dashboard), different root cause (event ordering: notification built from `TransferRequested` instead of `TransferCompleted`, per Ravi Kumar), and already has a fix in progress. It's a related-but-distinct bug; not currently linked to the others in Jira.

There is a plausible causal link (inference, not stated in the tickets): the caching behaviour both BANK-425 and BANK-440 complain about was introduced by **BANK-419** ("Cache the balance response in local storage for 15 minutes"), shipped in 3.1.4, with no mention of invalidating the cache on transfer. This looks like a regression/gap left by BANK-419 rather than a coincidence, but none of the tickets explicitly link them.
