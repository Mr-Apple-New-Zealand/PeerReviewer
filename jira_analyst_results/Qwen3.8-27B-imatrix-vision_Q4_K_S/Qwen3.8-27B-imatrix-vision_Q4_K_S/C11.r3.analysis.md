## 1. Summary
Customers (and a test account) cannot log in to the mobile app (v5.4.1): after entering credentials the app shows an error dialog that blocks login and directs the user to log in to Online Banking and complete a questionnaire. The reporter reproduced it on a test account, so it is not customer-specific.

**Exact error text from the screenshot** (modal dialog over the "Enter your Online Banking credentials" screen):

> **Error!**
> To keep using mobile app, please log in to Online Banking and fill the customer's questionnaire.
> [OK]

(Note: "questionnaire" is misspelled in the app — likely "questionnaire".)

## 4. Risks and gaps
- **Ambiguous intended behaviour (core gap):** The dialog is phrased as an "Error!" but its body reads like an instruction to complete a questionnaire in Online Banking. It is unclear whether this is (a) a legitimate mandatory onboarding/verification step, (b) a regression where a warning became a hard block, or (c) a backend flag (e.g. "questionnaire incomplete") incorrectly returned for the test account. This must be clarified before coding.
- **Dead-end UX (inference):** The only control is "OK", which presumably dismisses the dialog and returns the user to the same login screen, leaving them unable to proceed from the app — consistent with "the customer is stuck."
- **Test-data contamination risk (inference):** The reproduction was done on a test account (`TESTRELAXLUX4`); if that account simply has an outstanding questionnaire, the "bug" may partly be expected data state rather than a code fault. Need to confirm with a clean account.
- **No related/duplicate tickets** are linked; cannot rule out overlap with other auth issues from this data alone.
- **No embedded suspicious instructions** were present in the ticket fields or comments (the dialog text is product UI, not a directive to the analyst).
