## Are any of these duplicates of BANK-440?

### BANK-425 – Duplicate of BANK-440

Both tickets describe the same defect: the web home/dashboard screen shows a stale balance after a transfer, in the same version (3.1.4), with no fix applied. The small wording differences are consistent with a single root cause:

| | BANK-425 (Sep 5) | BANK-440 (Sep 13) |
|---|---|---|
| Symptom | Home-screen balance stale after transfer | Dashboard balance stale after transfer |
| Refresh | "Refreshing the page does not help" | Not mentioned |
| Logout/login | Not mentioned | "Only updates after logging out and back in" |
| API | Not mentioned | "GET /api/user/balance returns the correct new balance" |

The two "workarounds" described are fully consistent with Hana Sato's root-cause note in BANK-425: the balance is cached in **local storage** (`BalanceCache`, 15 min TTL). A page refresh re-reads the same local-storage entry (still stale), while a logout/login cycle re-fetches from the API and overwrites the cache. Neither reporter knew about the other's ticket; there are no links between them.

**Recommendation:**
- **Keep BANK-425 as the tracking ticket** – it was filed first, already has a confirmed root cause and a concrete fix (clear `BalanceCache` on successful transfer), and Hana Sato has already investigated.
- **Close BANK-440 as a duplicate of BANK-425.** Add a comment linking the two, note that the API-side confirmation in BANK-440's description is useful corroboration, and merge any additional context into BANK-425.
- Assign BANK-425 to an owner (currently Unassigned). Given Hana Sato has already diagnosed it, she is the natural candidate.

### MOB-88 – Not a duplicate

Superficially similar symptom ("balance shown is wrong after a transfer"), but everything else differs:

- **Platform / component:** Mobile push-notification service (iOS + Android) vs. web front-end local storage.
- **Affected version:** mobile 5.4.0 vs. web 3.1.4.
- **Root cause (per Ravi Kumar):** The notification service builds its message from the `TransferRequested` event, which fires *before* the debit is applied. The fix is to switch to the `TransferCompleted` event.
- **Fix:** Backend event-subscription change – completely unrelated to the `BalanceCache` in the web front end.

**Recommendation:**
- **Keep open and independent.** No action needed beyond the already-in-progress fix. Ravi Kumar should confirm the event switch, test on both iOS and Android, and note the fix version when it ships.
- Add a "relates to" link to BANK-425/BANK-440 so the team can see the cluster of post-transfer balance-staleness bugs without confusing them.
