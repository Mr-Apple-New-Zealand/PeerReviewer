**Summary**  
BANK-412 is a high-priority bug where retrying a failed transfer after a timeout causes the source account to be debited twice while the destination is credited only once. This has affected three customers and is reproducible in staging. The root cause is a lack of idempotency and the absence of a single transaction for debit and credit operations.

**Current State**  
- **Status**: In Progress  
- **Assignee**: Priya Nair  
- **Blocking Factor**: Waiting on code review for PR #218, which implements a fix.  
- **Target Fix Version**: 3.2.0 (scheduled for 2026-09-24)  
- **Sprint**: Sprint 38 (ends 2026-09-22) — fix is likely to be delivered on time if review is completed promptly.

**Key Details**  
- **Steps to Reproduce**:  
  1. Log in on mobile web, initiate transfer between two own accounts.  
  2. Introduce >30s latency (e.g., via toxiproxy) between API and DB.  
  3. When "ERR_TXN_504" appears, tap Retry.  
- **Affected Components**: Transactions  
- **Affected Version**: 3.1.4  
- **Fix Version**: 3.2.0  
- **Acceptance Criteria**:  
  - Retry after timeout should not cause duplicate debits.  
  - Debit and credit must be atomic (in one DB transaction).  
  - Retry should use idempotency key to prevent duplicate processing.
