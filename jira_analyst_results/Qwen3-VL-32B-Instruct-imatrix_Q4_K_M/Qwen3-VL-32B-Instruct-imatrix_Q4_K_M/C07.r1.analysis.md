**Incident Timeline (BANK-450)**

- **09:31 NZST**: Transfer errors begin to appear in monitoring dashboards.
- **09:47 NZST**: Monitoring alert fires due to TransferErrorRate > 20%.
- **09:52 NZST**: Incident declared by Sam Okafor. Error rate at 64%.
- **10:05 NZST**: Marcus Reid reports 40+ support calls in last 15 minutes.
- **10:10 NZST**: Priya Nair suggests database issue due to slow queries.
- **10:24 NZST**: Sam Okafor identifies root cause: JWT signing key rotated in OPS-81, but Transactions API still using old key for validation. Error: "IDX10503: Signature validation failed".
- **10:31 NZST**: Sam Okafor initiates rollback of OPS-81 config deploy.
- **10:44 NZST**: Rollback complete. Transfer error rate drops to under 1%.
- **10:50 NZST**: Incident resolved.

---

**Time to Detect (TTD)**  
= Time from first error occurrence to incident declaration  
= 09:52 – 09:31 = **21 minutes**

**Time to Recover (TTR)**  
= Time from incident declaration to recovery (error rate under 1%)  
= 10:44 – 09:52 = **52 minutes**

*(Note: Some may calculate TTR from first error to recovery, which would be 09:31 to 10:44 = 73 minutes. However, standard practice uses incident declaration as the start point for TTR.)*

---

**Root Cause**  
The JWT signing key was rotated in config deploy **OPS-81** without updating the key used by the **Transactions API** for token validation. This caused the Transactions API to reject valid tokens signed with the new key, resulting in 401 errors for all transfer requests.

This was confirmed by Sam Okafor in the comment at 10:24 NZST:  
> “The config deploy at 09:30 (OPS-81) rotated the JWT signing key for the Auth service. Auth started issuing tokens signed with the new key, but the Transactions API still validates against the old key.”

**Additional Notes**

- The incident affected all users, as confirmed by the 64% error rate and support queue spike.
