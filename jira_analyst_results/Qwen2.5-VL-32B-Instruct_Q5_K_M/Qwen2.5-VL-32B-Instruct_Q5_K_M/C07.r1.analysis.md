### Incident Timeline, Metrics, and Root Cause Analysis

#### **Summary**
The incident involved widespread failures in user transfers due to a mismatch between the JWT signing key used by the Auth service and the one validated by the Transactions API. The issue was triggered by a configuration deploy (OPS-81) that rotated the JWT signing key without updating the validation key on the Transactions API.

   - **09:30 NZST**: Configuration deploy (OPS-81) rotates the JWT signing key for the Auth service.  
     - Auth starts issuing tokens signed with the new key, but the Transactions API continues to validate against the old key.

### **Root Cause**
The root cause was identified as a mismatch between the JWT signing key used by the Auth service and the key validated by the Transactions API. Specifically:
- The configuration deploy (OPS-81) rotated the JWT signing key for the Auth service.
- This change was not propagated to the Transactions API, which continued to validate tokens against the old key.
