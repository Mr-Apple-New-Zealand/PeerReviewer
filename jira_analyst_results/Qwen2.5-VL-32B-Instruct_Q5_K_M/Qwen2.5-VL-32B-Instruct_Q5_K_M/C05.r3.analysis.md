### Analysis of BANK-440 and Related Tickets

#### **Summary**
BANK-440 reports that the web dashboard balance does not update after a successful transfer, requiring a logout/login cycle for the correct balance to appear. The API returns the correct balance immediately, indicating a frontend caching issue.

---

### **Are any of these tickets duplicates of BANK-440?**

#### **BANK-425: Account balance stale on home screen after moving money**
- **Summary**: Customers report that the web dashboard balance is out of date after a transfer. Refreshing the page does not help.
- **Key Details**:
  - The issue is described as affecting the web frontend, specifically the home screen.
  - Hana Sato identified that the web frontend caches the balance in local storage for 15 minutes and that this cache is not invalidated after a transfer.
- **Inference**: This ticket describes the same underlying caching issue as BANK-440. The stale balance problem on the web dashboard is caused by the `BalanceCache` not being cleared after a successful transfer.

**Conclusion**: **BANK-425 is a duplicate of BANK-440.**

---

#### **MOB-88: Push notification after transfer shows pre-transfer balance**
- **Summary**: The push notification for transfers on mobile devices displays the old balance instead of the new one.
- **Key Details**:
  - The issue is specific to mobile push notifications, not the web dashboard.
  - The root cause is that the notification service uses the `TransferRequested` event (before the debit is applied) instead of the `TransferCompleted` event.
- **Inference**: This ticket addresses a separate caching or timing issue in the mobile push notification system. While it involves balance updates, it does not overlap with the web dashboard caching problem described in BANK-440.

**Conclusion**: **MOB-88 is not a duplicate of BANK-440.**

---

#### **BANK-419: Reduce API calls on dashboard by caching balance**
- **Summary**: A task to cache the user's balance in local storage for 15 minutes to reduce API calls.
- **Key Details**:
  - The task was completed and shipped in version 3.1.4, introducing the `BalanceCache` mechanism.
  - This is the root cause of the stale balance issue reported in BANK-440 and BANK-425, as the cache is not invalidated after a transfer.

**Conclusion**: **BANK-419 is related to BANK-440 but is not a duplicate. It is the task that introduced the caching mechanism causing the issue.**
