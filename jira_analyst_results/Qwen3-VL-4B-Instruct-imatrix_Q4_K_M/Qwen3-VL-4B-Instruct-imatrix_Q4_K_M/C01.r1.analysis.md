**Summary:**  
A transfer retry after a timeout on mobile web causes the source account to be debited twice while the destination is credited once, due to lack of idempotency and transaction isolation. This results in financial discrepancies requiring manual reversal.

**Current state:**  
- **Status:** In Progress  
- **Assignee:** Priya Nair  
- **Resolution:** Unresolved  
- **Due date:** None (but target release is 3.2.0 on 2026-09-24)  
- **Blocking:** Code review of PR #218 is pending.

**Key details:**  
- **Steps to reproduce:**  
  1. Log in mobile web, start transfer between own accounts.  
  2. Introduce >30s latency (toxiproxy).  
  3. Tap Retry after “Request timed out (ERR_TXN_504)”.  
- **Affected components:** Transactions, mobile web.  
- **Affected version:** 3.1.4  
- **Fix version:** 3.2.0  
- **Acceptance criteria:**  
  - One debit, one credit per transfer.  
  - Retry should not create duplicate debits.  
  - Transaction must be atomic (debit + credit in one DB transaction).  
  - Idempotency key must be sent on retry.

- **Customer impact:** Three customers affected; Finance Ops must manually reverse debits.  
- **Platform gap:** Desktop web does not have retry, suggesting the issue is mobile-specific.
