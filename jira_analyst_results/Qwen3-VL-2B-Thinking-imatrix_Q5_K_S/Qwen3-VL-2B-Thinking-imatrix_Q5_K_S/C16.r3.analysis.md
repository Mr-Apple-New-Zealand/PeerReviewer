### Summary  
The Statements API's performance degraded significantly after version 4.7.0 release, causing users to experience timeouts or 5+ minute load times when accessing statement data. The regression manifests as long-running requests (exceeding 10s) for core operations like `GetStatementLineQuery` and `GetAccountSummaryQuery`, with the latter being the most critical bottleneck.  

### Current State  
- **Status**: Open (Unresolved)  
- **Owner**: Tom Becker (assigned to 4.7.0 release review)  
- **Blocking issue**: API throttling due to unresponsive requests; customers report callbacks due to 5+ minute delays.  
- **Critical detail**: Log analysis confirms requests exceed threshold (10s) at ~85% of the time window.  

### Key Details  
**Reproduction Steps**:  
1. Visit customer's statement page after release 4.7.0.  
2. Observe browser timeouts or "loading" state for >1 minute.  
3. Confirm same 5+ minute window in both log files (before/after release).  

**Affected Components**:  
- **API**: `statements-api` (versions 4.6.3 → 4.7.0)  
- **Queries**: `GetStatementLineQuery`, `GetAccountSummaryQuery` (dominated by the latter).  

**Critical Evidence**:  
- **Before release** (Sep 13):  
  - `GetAccountSummaryQuery` avg. time: 3102ms (15.5s).  
  - No errors; log shows health check "Healthy".  
- **After release** (Sep 15):
