# Analysis of Statements API Regression Post-Release 4.7.0

## Summary
Since release 4.7.0, opening a customer's statement takes over a minute or times out in the browser, causing branch staff to advise customers to call back. The logs show significant regression in the statements API's performance where the GetStatementLineQuery request is now taking significantly longer than before the release.

## Current State
- **Status**: Open (Unresolved)
- **Owner**: Tom Becker (Assignee)
- **Blocking issue**: The statements page is unusable for customers due to timeouts and long-running queries
- **Known impact**: Customers reporting statement view issues since 4.7.0 release

## Key Details
### Log Analysis
| Metric | Before Release (9/13) | After Release (9/15) | Regression |
|--------|-----------------------|----------------------|------------|
| GetStatementLineQuery Time | 281 ms (0.28s) | 35171 ms (35.17s) | 34.89s |
| GetAccountSummaryQuery Time | 3102 ms (3.1s) | 3188 ms (3.188s) | 0.088s |
| Critical Warning | None | "Long-running request GetStatementLineQuery took 35171ms" | 35.17s |
| ThreadPool Starvation | None | "ThreadPool starvation detected: 31 work items queued, 0 threads available for 4200ms" | Severe |

### Critical Observation
- The GetStatementLineQuery request time has increased by **34.89 seconds** (35.17s - 0.28s)
- The log shows multiple "Long-running request" warnings for GetStatementLineQuery (35.17s, 35.17s, 44.335s)
- Thread pool starvation detected (31 work items queued, 0 threads available)

### Technical Context
- The logs indicate the release (4.7.0) contains no specific changes to the statements API
- The "Long-running request" warnings suggest the issue is related to the database query
- The statement line query is the most affected component, with the request time exceeding the threshold of 10,000ms (10s)

## Risks and Gaps
1. **Ambiguity**: The ticket states the release didn't contain changes to the statements API, but the logs show the issue is in the statements API. The release notes don't mention this issue.
2. **Missing Information**: 
   - The exact nature of the database query (e.g., database schema, indexing, query optimization)
   - How the "Long-running request" warnings were handled in the release notes

3. **Dependency Issues**: 
   - The thread pool starvation suggests resource constraints, but there's no information about resource limits or configuration changes
   - No visibility into why the statement line query is being handled longer than expected
