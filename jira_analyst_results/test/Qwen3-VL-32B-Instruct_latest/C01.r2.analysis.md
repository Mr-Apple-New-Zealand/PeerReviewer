**Summary**  
BANK-412 is a high-priority bug where retrying a failed transfer after a timeout causes the source account to be debited twice while the destination is credited only once. This has affected three customers and is reproducible on mobile web in version 3.1.4. The root cause is a lack of idempotency and atomicity in the transfer process.

**Key Details**  
- **Steps to Reproduce**:  
  1. Log in on mobile web and initiate a transfer between two own accounts.  
  2. Introduce >30s latency (via toxiproxy) between API and DB.  
  3. When ERR_TXN_504 appears, tap Retry.  
  → Result: double debit, single credit.  

- **Affected Components**: Transactions  
- **Affected Version**: 3.1.4  
- **Fix Version**: 3.2.0  
- **Environment**: Mobile web (not reproducible on desktop web, which disables Retry after timeout)  
- **Acceptance Criteria**:  
  - Retry should not cause duplicate debits.  
  - Debit and credit must be atomic (in one DB transaction).  
  - Idempotency key must be respected on retry.
