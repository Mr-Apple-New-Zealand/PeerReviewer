**BANK-412 analysis**

**Summary**
BANK-412 is a High priority bug in the Transactions component where a mobile-web account transfer retried after a timeout ERR_TXN_504 results in the source account being debited twice while the destination is credited once. Three customers have reported the issue on 5, 6 and 8 September. The fix is targeted for 3.2.0.

**Current state**
* Status: In Progress. Assignee: Priya Nair. Reporter: Marcus Reid.
* Last update: 2026-09-12 16:40. Sprint 38 is 2026-09-09 to 2026-09-22; today is 2026-09-15.
* Blocking: PR #218 is open per Priya Nair 2026-09-12 16:40. It wraps debit and credit in a single DB transaction and adds Idempotency-Key header support to POST /api/transaction/transfer. Waiting on code review.
* Affects version: 3.1.4. Fix version: 3.2.0. Target release noted by Aroha Walker 2026-09-11 is 2026-09-24.

**Key details**
* Steps to reproduce are provided for staging: mobile web transfer, inject >30s latency with toxiproxy, trigger ERR_TXN_504, tap Retry.
* Affected component: Transactions. Labels: customer-impact, mobile-web.
* Expected vs actual: Expected one debit and one credit. Actual two debits, one credit. Log excerpt shows txn=8841 debit committed then credit timeout, followed by txn=8842 debit committed and credit committed.
* Acceptance criteria: Not explicitly listed in the ticket. Expected behaviour is described in description but no formal acceptance criteria field is present.
* Missing: Due date is None. No links or attachments. No explicit client-side idempotency key generation requirement documented.

**Risks and gaps**
