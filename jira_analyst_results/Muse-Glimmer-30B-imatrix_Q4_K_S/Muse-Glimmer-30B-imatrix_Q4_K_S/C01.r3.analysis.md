**BANK-412 Analysis**

**1. Summary**
BANK-412 is a high-priority bug on mobile web where retrying a transfer after a timeout `ERR_TXN_504` causes the source cheque account to be debited twice while savings is credited once. The issue is reproduced on 3.1.4 and affects customers; three reports are logged for 5, 6 and 8 September 2026.

**2. Current state**
* Status: In Progress. Assignee: Priya Nair. Reporter: Marcus Reid.
* Last update: 2026-09-12 16:40. Sprint 38 2026-09-09 to 2026-09-22, story points 5.
* Progress: Reproduced in staging by Priya Nair and confirmed by Tom Becker on 3.1.4 staging. Desktop web is not affected per Tom Becker 2026-09-10.
* Blocking: Code review for PR #218. Priya Nair 2026-09-12 states PR is open and wraps debit+credit in a single transaction and adds Idempotency-Key header support to the transfer endpoint, waiting on code review.

**3. Key details**
* Affects versions: 3.1.4. Fix versions: 3.2.0. Component: Transactions. Labels: customer-impact, mobile-web.
* Steps to reproduce provided: mobile web transfer between own accounts, >30s latency via toxiproxy, tap Retry on ERR_TXN_504.
* Expected: one debit and one credit. Actual: two debits, one credit.
* Log evidence from description: txn=8841 debit committed 2026-09-08 09:41:02, credit failed timeout 09:41:32; txn=8842 debit committed 09:41:40, credit committed 09:41:41.
* Root cause as stated in ticket:
  1. Retry button calls POST /api/transaction/transfer again with no idempotency key, so server treats it as new transfer. Priya Nair 2026-09-09.
  2. Debit and credit are not in one database transaction, so first debit stays committed when credit times out. Priya Nair 2026-09-09.
* Missing: Explicit acceptance criteria, test results, and confirmation that the client will persist and resend the same Idempotency-Key on retry. No links or attachments are present.
