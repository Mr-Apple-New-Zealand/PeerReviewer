### Underlying defect – inference
Inference based on the event:
* The session started healthy and the user performed normal allocation queries and actions for >1 hour.
* After a long tab-open duration, a series of API calls start returning 401. This suggests the authentication token became invalid/expired and the UI did not recover gracefully.
* Immediately after the 401s, the UI code attempts to read properties on the empty/error responses, producing `reading 'rows'`, `reading 'returnProperties'`, `reading 'length'`, and the reported `reading 'sort'`. This is consistent with code assuming a successful response shape and calling `.sort` on an array that is undefined because the response was null/empty due to auth failure.
* Tom Becker’s comment that “something is calling .sort on an array that isn't there” matches the captured exception type, but the breadcrumbs show the error is part of a cascade after auth failures rather than an isolated sort bug.

Fact: The ticket description states the error is “Cannot read properties of undefined” on the batch actions screen and the screen goes blank. The event confirms TypeErrors on that screen after 401s.
