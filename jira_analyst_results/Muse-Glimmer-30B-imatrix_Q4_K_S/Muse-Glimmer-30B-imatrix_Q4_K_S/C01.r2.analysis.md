**BANK-412 Analysis**

**1. Summary**
BANK-412 is a High priority bug on mobile web where retrying a timed-out transfer debits the source cheque account twice while crediting savings once. It is reproducible on version 3.1.4 with artificial latency and has impacted three customers on 5, 6 and 8 September. Fix is targeted for 3.2.0 release on 2026-09-24.

**3. Key details**
* Steps to reproduce from description: log in on mobile web, start transfer between own accounts, add >30s latency via toxiproxy, when ERR_TXN_504 appears tap Retry.
* Expected: one debit and one credit. Actual: two debits, one credit.
* Log excerpt shows debit committed txn=8841, credit failed timeout, then debit committed txn=8842 and credit committed txn=8842.
* Root cause as reported in comments:
  * Priya Nair 2026-09-09 11:02: Retry button calls POST /api/transaction/transfer again with no idempotency key, server treats it as new transfer.
  * Debit and credit are not in one database transaction, so first debit stays committed when credit times out.
* Confirmation: Tom Becker 2026-09-10 14:20 confirms on 3.1.4 staging with Priya's steps. Does NOT reproduce on desktop web: desktop disables submit button and has no Retry button after timeout.
