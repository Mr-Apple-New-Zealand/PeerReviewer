### Risks and gaps
* Conflict between reporter explanation and log evidence. Marcus Reid comment 2026-09-15 18:44 claims keys stored in non-persisted directory and no XML encryptor means keys are junk and notifications are failing. The log shows Data Protection warnings only, no Data Protection errors, and shows clear SMTP authentication failures.
* Inference: The root cause is likely SMTP auth, not Data Protection. Based on log, SMTP server is rejecting basic authentication: `5.7.139 Authentication unsuccessful, basic authentication is disabled`. Restarting the pod will not fix authentication.
* Growing outbox with fixed 5s retry and no backoff / no dead-letter path risks resource exhaustion and repeated failures.
* No previous container log, so cannot confirm when failures began relative to 14:00 report. Cannot confirm if Data Protection key loss contributed at any time.
* No information on recent changes to SMTP provider, secrets for `svc-notify@example.com`, or Platform changes around 14:00.
